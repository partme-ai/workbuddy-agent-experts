# Rust README 剖面：纯设计阶段

> 适用于尚无 `Cargo.toml`、尚无可构建实现，或只有架构、迁移和实施计划的 Rust 项目。该剖面替换母模板中的安装、运行、测试、覆盖率和发布章节。

## 首屏状态声明

在项目标题后立即写明：

```markdown
> **项目状态：设计阶段**
>
> 当前仓库尚未提供可构建的 Cargo workspace、可安装 crate 或稳定公共 API。
> 本 README 描述已确认的目标、设计决策和实施边界，不代表功能已经可用。
```

必须删除：crates.io/docs.rs 徽章、`cargo add`、可运行快速开始、测试通过、覆盖率、性能结果和发布说明。

## 计划中的 Workspace

```text
planned-workspace/
├── Cargo.toml                 # 尚未创建
├── crates/
│   ├── {core-crate}/          # 核心 trait 与模型
│   ├── {adapter-crate}/       # 框架或平台适配
│   └── {facade-crate}/        # 用户入口
└── tests/                     # parity / integration / golden
```

| 计划 crate | 预期职责 | 允许依赖 | 禁止依赖 | 完成条件 |
|---|---|---|---|---|
| `{core}` | 契约和核心规则 | std/minimal | Web/runtime | API + unit tests |
| `{adapter}` | 外部框架适配 | core + framework | 反向污染 core | integration tests |

所有名称都应标记为“计划”，直到 manifest 实际存在。

|---|---|---|---|---|---|
| `ADR-001` | `{decision}` | `{evidence}` | `{alternatives}` | `{condition}` | 已确认/提议 |

## 阶段计划与退出条件

| 阶段 | 交付物 | 退出条件 | 依赖 | 风险 |
|---|---|---|---|---|
| Phase 0 | Workspace 和 CI | fmt/clippy/test 可运行 | toolchain | 依赖选择 |
| Phase 1 | 最小核心 API | 一个真实场景端到端通过 | Phase 0 | 设计漂移 |
| Phase 2 | 适配和兼容 | 兼容矩阵目标通过 | 上游 fixtures | 语义差异 |
| Phase 3 | 发布准备 | package dry-run 和文档通过 | 稳定 API | 发布顺序 |

时间估计只能作为计划，不应写成承诺；优先使用可验证退出条件。

## 未来快速开始（禁止伪装为当前用法）

若保留 API 草图，必须使用明显标题：

```markdown
## 设计草图：未来可能的 API（当前不可运行）
```

并注明：名称、签名、crate 和配置均可能变化。不要提供 `cargo add`，避免读者误以为已发布。

## 从设计阶段转为实现阶段

只有同时满足下列条件，才切换回 Rust 母模板的常规章节：

- 根 `Cargo.toml` 和计划 crate 已存在；
- 最小示例在干净环境可运行；
- CI 实际执行 fmt、Clippy 和测试；
- README 中的 API 来自源码而非设计草图；
- 发布徽章只在 registry/docs 页面真实存在后添加；
- 成熟度仍按实验性/预览/稳定分别声明。

## 文档一致性审计

重点搜索设计文档中这些容易造成误解的表述：

- “已实现”“全部通过”“生产可用”；
- 不存在的源码路径、crate 和 CI 文件；
- 未发布的 registry 版本；
- 计划测试数量和覆盖率目标被写成结果；
- 指南中的命令没有“未来设计”标识。
