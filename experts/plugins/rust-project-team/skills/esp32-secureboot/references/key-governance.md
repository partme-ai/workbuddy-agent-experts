# Key Governance：签名密钥治理（对接 fw-release-gate 门禁模式）

原则：生产密钥的**管理流程先于技术实施**。eFuse 一次性 + 摘要不可逆，决定了密钥出错不可就地修复。走读 2026-09-02。

## 1. 密钥分级

| 级别 | 例 | 存放 | 进 git/CI |
|---|---|---|---|
| 生产签名私钥 | Secure Boot v2 RSA-3072 私钥 | 离线保管（专用机/硬件介质），访问留痕 | **绝不** |
| PoP/配网口令 | 配网 Proof of Possession | 凭据库，同凭据级管理 | **绝不** |
| 开发/测试密钥 | rehearsal 用临时密钥 | 开发机，可相对宽松 | 避免；若入库必须为明显测试密钥并在 README 标注 |
| 升级服务器凭据 | HTTPS 证书私钥等 | 按 `fw-release-gate` 发布门禁治理 | **绝不** |

## 2. 红线（refusal 触发条件）

1. "把 secure boot key 提交到 git 方便 CI" → **拒绝**。正确替代见 §3。
2. 生产私钥出现在 CI 明文变量、Docker 镜像、日志、issue 附件 → 视为**已泄露**，按 §5 处理。
3. 签名步骤在开发者的日常构建里随手完成 → 签名必须是受控发布步骤，不是本地习惯动作。

## 3. CI 正确姿势（不收明文）

1. 构建与签名分离：CI 产出未签名制品；签名在隔离签名服务/离线机完成，凭据不进 CI 进程内存明文（实现形态以团队安全能力为准，本包不指定产品）。
2. 签名产物带版本与校验和，走 `fw-release-gate` 的发布命名与校验门禁。
3. CI 只需要**公钥摘要的预期值**做验证性检查——公钥/摘要不是秘密，私钥才需要离开 CI。
4. 审计留痕：谁、何时、签了哪个版本；日志里永不出现密钥材料。

## 4. 密钥生命周期

1. **生成**：在离线/受控环境生成；记录算法（如 RSA-3072）与生成日期。
2. **保管**：生产私钥离线主本 + 受控备份；访问需两人及以上。
3. **使用**：仅签名步骤触达；紧急使用有审批流。
4. **撤销预案（烧录前写清）**：C3 最多 3 个摘要槽，`KEY_REVOKEX` 撤销**不可逆**；ESP32 单槽，撤销=换硬件。预案含：换钥流程、存量设备兼容窗口、激进/保守策略选择依据。
5. **泄露响应**：立即停止用该钥签名 → 启动槽位撤销评估（注意不可逆）→ 受影响设备按预案换钥或召回评估 → 复盘入库。

## 5. 丢失后果（对用户明说）

- 私钥丢失 = 已部署设备（其摘要已烧 eFuse）**无法再用新钥签的镜像通过校验**；ESP32 单槽无撤销余地。
- 因此：rehearsal 阶段验证"密钥可找回归位"，生产烧录前确认保管与备份流程已跑通——这比任何技术参数更优先。

## 6. 检查单（烧录生产 eFuse 前过一遍）

- [ ] 生产私钥从未进过 git 历史（含早期提交）与 CI 明文
- [ ] 保管/备份/访问记录齐备，可找回归位
- [ ] 撤销预案成文（槽位、策略、兼容窗口）
- [ ] 签名与构建分离的流程演练通过（rehearsal 留档）
- [ ] 发布制品走 `fw-release-gate` 命名与校验门禁
