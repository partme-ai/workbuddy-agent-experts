# 架构文档领域剖面选择器

> 与 `../架构设计文档模板.md` 组合使用。母模板负责架构合同的共有部分，剖面负责系统类型差异。

## 选择矩阵

| 系统特征 | 必选剖面 | 常见组合 |
|---|---|---|
| 服务器应用、桌面运行时、Java/Rust/Python 服务或企业平台 | [运行时与应用平台](运行时与应用平台架构剖面.md) | 插件、消息、AI、可观测 |
| 通过插件、Hook、SPI、MCP、Channel 或 Adapter 扩展 | [插件与扩展体系](插件与扩展体系架构剖面.md) | 运行时、消息、安全 |
| 边缘节点、网关、路由器、单板机、MCU 或 RTOS 设备 | [边缘与嵌入式](边缘与嵌入式架构剖面.md) | 消息、可观测 |
| 消息代理、Stream、Pub/Sub、任务队列或事件桥 | [消息与事件驱动](消息与事件驱动架构剖面.md) | 插件、边缘、可观测 |
| Agent、模型、记忆、RAG、工具执行或多智能体 | [AI、Agent 与 RAG](AI-Agent与RAG架构剖面.md) | 运行时、插件、消息 |
| 监控采集器、管理平面、控制面、治理平台 | [可观测性与控制面](可观测性与控制面架构剖面.md) | 运行时、插件、消息 |

## 组合规则

```text
系统架构母模板
  + 主系统类型剖面（通常 1 个）
  + 横切能力剖面（0～3 个）
  - 不适用的母模板章节
  = 最终架构文档
```

## 输出文件名

| 语言 | 强制格式 | 示例 |
|---|---|---|
| 英文或默认语言 | `*-Architecture.md` | `ExamplePlatform-Architecture.md` |
| 中文 | `*-Architecture.zh_CN.md` | `ExamplePlatform-Architecture.zh_CN.md` |

组件、子系统和版本放在 `Architecture` 之前，例如：

- `ExamplePlatform-Gateway-Architecture.md`
- `ExamplePlatform-Gateway-Architecture.zh_CN.md`
- `ExamplePlatform-V2-Architecture.zh_CN.md`

不允许使用 `*_Architecture_CN.md`、`*-Architecture_CN.md`、`*-Architecture.zh-CN.md`、`*-architecture.md` 或中文标题作为输出文件名。

示例：

```text
企业运行平台 = 母模板 + 运行时平台 + 插件扩展 + 可观测控制面
边缘设备节点 = 母模板 + 边缘嵌入式 + 消息事件
Agent 知识服务 = 母模板 + AI/Agent/RAG + 运行时平台 + 可观测控制面
消息渠道插件 = 母模板 + 插件扩展 + 消息事件
```

## 互斥与裁剪

- MCU 不应保留服务器集群、动态类加载和无限制并发示例。
- 纯监控插件不应拥有业务权威状态或修改核心业务语义。
- 消息系统必须明确 ACK、幂等、顺序和死信；普通同步 API 不必强行引入。
- AI/RAG 章节必须区分确定性控制流与非确定性模型输出。
- 插件架构不能把宿主内部实现泄漏为稳定插件合同。
- “目标态、当前骨架、平台边界”适用于任何尚未完整落地的复杂能力。

## 组合后的检查

- [ ] 只有一个 H1，章节重新编号
- [ ] 每张图都有输入、边界、处理和输出
- [ ] 母模板与剖面没有重复定义同一状态、配置或协议
- [ ] 当前态、目标态、非目标和平台边界分开
- [ ] 关键数字来自实测或明确标为预算
- [ ] 源码、部署、配置、协议和测试中的命名一致
- [ ] 最终文档不包含私有项目名、本机路径或真实秘密
- [ ] 文件名严格匹配 `*-Architecture.md` 或 `*-Architecture.zh_CN.md`
