# 前台操作与执行策略

适用于个人创作者或团队在一个已授权的本地工程中设计、检查和导出；不同项目使用不同
session 和输出目录。先读取状态，再选择下面的流程，不要重新询问已明确的用户决定。

## 快速开始

- “在 Blender 前台做白模，允许原创缺失素材，导出 blend 和 mp4”：自动模式，传递明确目录与格式。
- “每个阶段先让我看”：交互模式，保留阶段审阅。
- “只看看这个工程有什么问题”：只读模式，不建模、不导出。

## 公开命令

命令通过 `harness_cli.py --descriptor <private-descriptor> --request <json-file>` 发送。
JSON 保留协议规定的 sessionId/requestId/transactionId；内容修改使用最新 expectedSceneRevision。
下表是 `arguments`，不包含令牌。令牌由 CLI 从私有 descriptor 读取，不输出给用户。

| command | arguments | 可观察结果 |
|---|---|---|
| `session.status` | `{}` | 实际策略、revision、暂停状态、阶段、变化对象、最近错误 |
| `session.set_progress` | `{"stage":"制作相机路线","progress":0.4}` | 前台面板与视口标题显示阶段；进度仅表示调用方报告 |
| `view.set` | `{"view":"CAMERA"}` | 相机视图；也支持 FRONT、SIDE、TOP |
| `view.present` | `{}` | 在正确会话中打开一个审阅窗口；重复调用复用该窗口，不创建更多窗口 |
| `view.focus` | `{"object":"Hero"}` | 聚焦指定对象，不改变模型变换 |
| `playback.set_frame` | `{"frame":84}` | 跳到帧范围内的指定帧，不新增关键帧 |
| `playback.set` | `{"playing":true}` | 开始播放；false 停止，重复请求不会反向切换 |
| `session.pause` | `{}` | 暂停设计，失效旧事务与导出审批，排队操作被取消 |
| `session.resume` | `{}` | 需用户授权 claim；前台 Resume 按钮也可恢复 |

## 能力边界

- 可做：前台展示、视图和播放控制、阶段报告、暂停/恢复、已授权目录内的新文件导出。
- 需具体输入：自动模式的输出目录和格式；聚焦对象的名称；相机视图需要有效相机；
  缺少参考素材且未允许原创代理时，先说明缺少什么并请用户提供。
- 暂不覆盖：实时录屏、正在运行的单个 Blender 操作的强制抢占、异步后台渲染和影视动作质量判定。
  付费渲染和长剧情统筹交由各自插件；此处不扩展这些接口。

## 暂停与恢复

用户点击 Pause / Take Over 后，允许检查和切视图，但停止新建、修改、提交事务和导出。
用户完成编辑并恢复后，必须重新 `scene.inspect`，再以新的 transactionId 建立快照。
旧事务返回 TRANSACTION_INVALIDATED，禁止用旧快照覆盖人工修改。
Revoke 或用户打开其他工程会关闭此会话；应重新连接用户选定的工程，不自动切回原文件。

## 常见误用

- 只在文字中说自动模式，却用默认启动参数：必须传启动参数并检查返回的实际策略。
- 把 progress=1 当成质量通过：仍须检查预览和交付物。
- 用户暂停后自己发 resume：等待用户明确恢复；授权不能由进度计划推断。
- 导出到同名文件：自动授权只覆盖新文件；使用新的版本文件名或取得覆盖授权。
- 界面没打开却宣称前台展示：FRONTEND_UNAVAILABLE 要解释为“没有可用的 Blender 3D 视口”。

## 操作问答

自动模式为什么还保留事务？事务记录版本与恢复点，无需为每次 commit 弹对话框。

只读模式能播放吗？可以播放和跳帧；不能修改物体、关键帧或导出最终文件。

暂停会立刻终止渲染吗？不会；暂停在结构化命令之间生效，长时间同步渲染属于后续优化。

前台面板会永久安装吗？Managed 面板仅在当前进程注册，不修改 Preferences；关闭会话时清理。

碰到错误怎么办？用中文描述具体对象或阶段、是否发生修改、应恢复还是重新连接；保留错误码供排查。

要不要上传日志？本地日志和 descriptor 不自动上传；报告中省略 token、授权 claim 和其他敏感内容。
