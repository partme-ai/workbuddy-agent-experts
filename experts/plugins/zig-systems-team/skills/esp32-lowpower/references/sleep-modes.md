# Sleep Modes — 双模式事实与电流实测方法

> 依据：firmware-skills 日期化基线 §8（ESP-IDF 官方 sleep_modes 文档，走读 2026-09-02，不自动更新）。
> 置信度标注随行给出；中置信项引用前运行时核验。

## 1. 双模式对比（高置信）

| 维度 | Light-sleep | Deep-sleep |
|---|---|---|
| CPU | 时钟门控（停） | 断电 |
| RAM | 状态保持 | 大部分断电；仅 **RTC FAST/SLOW 内存**供电 |
| 数字外设 | 时钟门控 | 断电 |
| 无线 | **断电** | 断电 |
| RTC 控制器 / ULP | 供电 | **供电** |
| 恢复点 | 从睡眠点继续（保持状态） | 复位流程重启（普通 RAM 内容丢失） |
| 适用 | 短间隔打盹、需快速恢复 | 长间隔（分钟~天）、占空比极低 |

要点：**"低功耗且保持连接"不成立**——两种模式无线都断电。连接保持/重连行为属无线协议栈细节，基线未收录，以官方 Wi-Fi/Bluetooth 电源管理文档为准（运行时核验）。

## 2. Deep sleep 后什么是活的（高置信）

- RTC 控制器（管唤醒）
- ULP 协处理器 / LP 核（形态按芯片：ESP32=ULP-FSM；S2/S3=RISC-V ULP 或 FSM；C6/P4=LP 核）
- RTC FAST/SLOW 内存（跨睡眠小状态的唯一 RAM 去处）

其余一切（普通 RAM、外设寄存器状态、任务栈）在唤醒后不保留——代码必须按"唤醒 = 走复位启动流程"来写。

## 3. RTC 内存保留 vs NVS 快照

- **RTC 内存**（`RTC_DATA_ATTR` 一族声明，具体宏以官方文档为准——运行时核验）：醒来即得，适合睡眠计数器、上次时间戳等小状态；容量以芯片规格为准（运行时核验）；换电池/掉电即失。
- **NVS 快照**（入睡前写）：flash 持久，掉电不丢；有写入寿命考量，禁止在高频循环里反复刷。
- 决策口诀：**跨睡眠找 RTC，跨掉电找 NVS；高频写入两边都别去，攒批再写。**

## 4. 电流实测方法（验收唯一依据）

背景：基线只确认深睡电流为"µA 数量级"；官方页仅给 SPI Flash 待机 <30µA / Deep Power-Down <1µA（高置信）。"典型 10µA / ULP ~150µA"出自数据手册**转述**（中置信），且是**芯片裸值，不是板级值**——外设漏电、上拉、LED、稳压器静态电流都可能放大数倍至数十倍。

步骤：

1. 功率计/源表**串联**进供电回路；记录供电方式（电池/Lab 电源）与电压。
2. 板上外设按产品真实配置连接（禁止"拆干净再测"——那测的是不该存在的乐观值）。
3. 进入目标睡眠模式，稳定 ≥5 分钟，取**平均电流**（瞬时闪断值不作数）。
4. 同法测工作相电流（采样/上报时段），与睡眠电流一起做占空比加权。
5. 续航估算：`续航 ≈ 电池可用容量 ÷ 加权平均电流`；报告必须附实测记录（供电方式、板级配置、均值）与估算假设。
6. 温度漂移、电池自放电、老化等长周期因素 → `fw-hil-testing` 长跑验收；未实测 = `Pending HIL`。

## 5. UNVERIFIED 清单（禁止当事实写）

- 深睡/轻睡具体 µA 数值（任何芯片）。
- 各芯片 RTC 内存容量、深睡电流与唤醒源逐芯片完整矩阵。
- light sleep 下的无线重连行为与耗时。
- 基线 6 类之外的唤醒手段（UART/蓝牙 wake 等）。

以上一律：查官方 sleep_modes/芯片数据手册（运行时核验）或板级实测，二选一，不背记忆。
