# Example Profiles

The bundled templates retain detailed examples from several product archetypes. Treat them as reusable examples, not as facts or mandatory architecture.

## Profile A: ExampleCommerce

- Product type: commerce SaaS and automation platform
- Typical concepts: products, orders, stores, pricing, fulfillment, analytics
- Primary use: root-level market, planning, domain, architecture, and menu examples

## Profile B: StoreOps

- Product type: mobile store operations application
- Typical concepts: store owner, staff, technician, work order, customer, service progress
- Primary use: research, requirements, PRD, testing, and release examples

## Profile C: ExampleConsole

- Product type: multi-instance software management console
- Typical concepts: instances, configuration baselines, deployment tasks, health, sessions, usage, logs
- Primary use: version architecture, version menu, module PRD appendix, and design-generation examples

## Reuse rules

1. Select the nearest profile before copying examples.
2. Replace domain nouns consistently across the entire document set.
3. Do not combine profiles unless the target product genuinely combines those domains.
4. Preserve the structure and level of detail while rewriting business facts, metrics, APIs, technologies, and acceptance criteria from project evidence.
5. Label retained blocks with `完整示例：<profile>` and end them with `示例结束` when a template contains both a fillable section and a complete case study.
