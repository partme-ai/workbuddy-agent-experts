# 导演插件开发计划

依据：../specs/plugin-design.md；前置：工作台 D02 MCP 接口及公共契约 0.1.0。当前所有实现任务未开始。这里不重复建立另一套需求事实源。

## 开发顺序

| 任务 | 计划文件/责任 | 可验证产物 |
|---|---|---|
| P01 契约锁定 | contracts.lock.json、tests/contract_cases/ | 固定上游 commit/hash，可解析正例，拒绝字段/引用反例 |
| P02 领域素材读取 | scripts/context_reader、相关 Skill | 分页、出处/版本、缺失输入与冷会话恢复 |
| P03 创作工作流 | plugins/codex-director/skills/，按下表顺序 | 用户目标到领域结构化候选 |
| P04 平台回填 | scripts/workbench_adapter、tests/integration/ | 真实 MCP 写入、幂等、revision冲突 |
| P05 领域评估 | evals/cases、evals/rubric、reports/ | 黄金案例、失败案例、人工/模型意见分离 |
| P06 分发与宿主验收 | 插件 manifest、宿主安装文档 | Codex/WorkBuddy实际能力矩阵与版本固定 |

步骤细化：
1. 剧本与约束读取：读取选定剧本、世界设定、时长、风格、已有资产与锁定项；上游 stale 时先记录影响。
2. 导演阐述：逐场定义情绪、叙事目的、视听节奏、表演重点；避免空泛的电影感形容词。
3. 调度与连续性：确定空间轴线、人物站位、视线、运动方向、动作与接触点、镜头入出状态。
4. 镜头意图：按场次定义建立/推进/反应/插入等覆盖需求，景别、焦距意图与时长区间；不过早制造具体机型承诺。
5. 生产路线规划：复杂空间/动作走 Blender 或已有 DCC，简单特写/环境可用参考图；给出依赖、费用未知项与质量风险。
6. 变更建议与交接：需要改剧本时发 ChangeProposal；保存 DirectorPlan 固定版本，交给 Storyboard 具体化。

这些路径是目标职责目录，不是已经存在的实现文件。实现语言优先复用宿主/工作台公开 JSON 接口的轻量工具，不从其他插件的 scripts 包导入私有类。

## 测试驱动执行

每任务先定义输入、期望输出与失败方式；对行为缺口编写失败案例；实现最小正确路径；运行目标/相关回归；最后用真实宿主打开项目验证 UI 已显示对应结果。

覆盖：剧本内容未授权变更、轴线冲突、角色瞬移、关键事件漏覆盖、时长不可拍、复杂镜头误选简单路线、旧剧本版本与导演方案混用。文件校验不替代领域评估；至少五个不同内容案例，其中一个含人工修订和上下游版本变化。

## 集成门禁

- [ ] 公共契约固定并通过样例验证。
- [ ] 领域 Skills 实现且逐个完成结构/TRACE 与行为评估。
- [ ] 工作台写入可从另一宿主会话读取。
- [ ] 相同 operation_id 重放无重复；stale revision 不覆盖。
- [ ] 候选、选定与验收状态分离。
- [ ] Codex 实际运行通过。
- [ ] WorkBuddy 配置、工具发现和实际运行通过，或明确标示尚不支持。
- [ ] 私有仓库版本发布、安装产物与源码一致性验证。

## 本轮交付状态

仅完成规格与开发规划；没有生成可安装插件，没有调用外部模型，没有增加费用。后续开发使用工作台 D03/D04/D05 中对应任务的排期，不把三份插件计划重复计算为新增阶段。
