# Stitch 屏幕走查视频：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 把 Transition 放到 Sequence 内 | 作为相邻 Sequence 的兄弟节点。 |
| 总帧数不减重叠 | 按场景之和减转场重叠。 |
| 短于20帧仍套20帧转场 | 缩短转场或延长场景。 |
| 下载失败破坏旧图 | 原子暂存，失败保留旧目标。 |
| render exit0即验收 | 检查实际首尾和转场图像。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理为门店预约三步流程制作视频的本地方案；需要补充：屏幕资产与实际尺寸（确定来源）、顺序、时长、帧率和输出比例（决定映射）、已有 Remotion 工程及可用依赖（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。
