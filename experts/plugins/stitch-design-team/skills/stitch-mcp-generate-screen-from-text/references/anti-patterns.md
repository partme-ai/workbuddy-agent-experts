# Stitch 文本生成屏幕：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 把旧 modelId 清单当永远有效 | 检查实时工具schema，未暴露则省略。 |
| list_screens 的projectId格式硬编码 | 按当前工具schema传参。 |
| 调用前未准备 prompt | 先完成三段结构与系统分流。 |
| sessionId当屏幕ID | 读取list_screens/get_screen取得真实ID。 |
| 重试或清理时顺便删项目 | 非幂等写先对账，删除另需明确确认。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理按已准备提示生成门店预约移动页的本地方案；需要补充：真实纯 projectId 字符串（确定来源）、结构明确且无敏感内容的 prompt（决定映射）、当前工具schema接受的deviceType及可选modelId（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
