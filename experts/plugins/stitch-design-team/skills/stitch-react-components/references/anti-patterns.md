# Stitch 转 React 组件：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 用示例 style-guide 当项目主题 | 从当前 HTML 提取到项目本地。 |
| AST 通过就称导航正常 | 实际验证 Link 目标与桌面首页入口。 |
| 把动态 className 当脚本已覆盖 | 人工审查或项目样式检查补足。 |
| 为每次同步覆盖旧资产 | 按范围刷新并保留 provenance。 |
| 把 screenId 转数字 | 原样保留字符串。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理把门店预约 Stitch 页转 React 组件的本地方案；需要补充：目标 React 工程与现有工具链（确定来源）、指定 Stitch 屏幕或有来源的缓存资产（决定映射）、路由表、主题和组件行为契约（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
