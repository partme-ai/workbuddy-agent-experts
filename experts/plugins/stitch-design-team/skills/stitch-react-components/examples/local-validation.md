# Stitch 转 React 组件：本地应用验证

以下是完整的中文请求与预期响应契约，使用演示资料；不是远程执行记录。不调用 Stitch 写操作即可检索、模拟应用并审阅结果。

## 快速开始

输入：“把门店预约 Stitch 页转 React 组件。只用演示素材，先返回本地结果与验证范围。”

输出：输入桌面顶栏“门店预约”与路由 / → 使用既有路由 Link to="/"；截图与 HTML 来源记录在 .stitch；AST 通过不替代浏览器点击测试。

验证：AST 仅证明解析、Props 和字面 className hex 检查；若示例无远程环境，明确远程状态未执行。

## 典型场景

输入：“修复桌面品牌标识没有返回首页的问题；范围限当前需求。”

输出：按顺序列出从当前 HTML 和 DESIGN.md 提取 token 到目标工程，避免覆盖安装 Skill 的示例资源。 拆组件、数据与 hooks，使用 readonly Props；保持目标项目约定。 接入既有路由；品牌 logo 和桌面导航可返回首页，移动底栏隐藏时桌面仍有入口。 最后返回已处理对象与来源，未运行的项目单列。

验证：所有主题角色来源于当前设计。

## 高级场景

输入：“将新的设计 token 同步到已有 React 页面；定制参数为页面范围、目标目录、路由器、主题模式、刷新策略。”

输出：保留所选参数、同步来源；桌面/移动导航核对；AST 能力边界，提供首页链接和各路由都有可验证目标的判据；假设不冒充实际配置。

## 异常处理

输入：“把门店预约 Stitch 页转 React 组件，但暂时缺少目标 React 工程与现有工具链。”

输出：“先给本地假设草案。需要补充：目标 React 工程与现有工具链，用于确定真实来源；未执行依赖该来源的写操作。”不返回空答复，也不伪造成功。

## 避免误触发与验证

输入：“React Native 原生界面，不扩大任务。”

输出：“使用stitch-react-native；交接当前素材和请求，当前入口不执行额外动作。”

检查：以上五种请求分别检索快速、典型、高级、失败、边界路径；检查输出中的 ID、token、运行结论是否均有输入/回执依据。此人工应用检查不等价于独立模型触发率统计。
