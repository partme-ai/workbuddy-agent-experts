# 从源码提取设计系统：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 把两个近似色直接合并 | 保留原值与用途，合并作为建议单列。 |
| 把 Tailwind 默认值当项目事实 | 读取当前版本配置和 CSS 后记录。 |
| 构建失败就不输出 | 从可读源码生成部分文档并列缺失来源。 |
| 编造 hover/focus 状态 | 不存在的状态标为待确认建议。 |
| 把源码推断称为视觉验收 | 只报告源码提取，截图另行验证。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理从企业微信预约 Web 页的 CSS 提取主色与间距的本地方案；需要补充：前端源码根目录（确定来源）、主题、CSS 或组件文件（决定映射）、目标主题及是否需要上传兼容 YAML（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。
