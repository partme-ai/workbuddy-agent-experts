# Stitch 视觉风格提案：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 强制所有界面禁 Inter/紫色 | 将风格偏好视为建议，遵循批准品牌。 |
| 每个控件无限动画 | 限制必要反馈并支持 reduced-motion。 |
| 用英文字体遗漏中文回退 | 指定中文系统字体并验字重。 |
| 用假数字填满看板 | 演示标记或空态，不当事实。 |
| 手机强制一列导致表格不可读 | 按内容设计滚动/分组，实际验证。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理为门店预约品牌写克制的中文视觉提案的本地方案；需要补充：品牌素材与页面目的（确定来源）、目标受众、视口和已有约束（决定映射）、密度、变化程度、动效偏好（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
