# 提取静态 HTML 快照：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 删掉 style 再补 CDN | 保留 CSSOM 和本地样式，列出无法内联项。 |
| 硬编码登录密码 | 使用环境变量或已有合法演示会话。 |
| 缺 Puppeteer 就全局安装 | 报告缺少 puppeteer/tsx 和安装范围。 |
| 跨目录图片被内联 | post_process 限定资源根和允许类型。 |
| 图表空白仍称完成 | 使用 --inline-canvas 后检查图像，不支持则列缺失。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理保存门店预约 Web 页的空列表状态的本地方案；需要补充：获准访问的本地 URL 或静态入口（确定来源）、视口、目标状态及输出文件路径（决定映射）、现有 Node/Puppeteer/tsx 工具；登录页需合法演示会话（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
