# Stitch 转 React Native：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 把 div 原样复制 | 换 View，文本独立 Text。 |
| 认为 RN flex 默认为 row | 显式决定 flexDirection。 |
| 外层 ScrollView 包长 FlatList | 用列表头尾或 View 避免嵌套滚动。 |
| AST 通过就称真机通过 | 分别记录 AST/类型/平台验收。 |
| 所有屏幕强制刷新并覆盖缓存 | 仅刷新授权范围且保留来源。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理将门店预约稿转 iOS/Android 表单的本地方案；需要补充：目标 RN 工程与实际依赖版本（确定来源）、所选 Stitch 屏幕或获准复用的 HTML/截图（决定映射）、平台、导航及 token 约束（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
