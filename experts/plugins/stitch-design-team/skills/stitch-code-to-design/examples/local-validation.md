# 前端源码导入 Stitch：本地应用验证

以下是完整的中文请求与预期响应契约，使用演示资料；不是远程执行记录。不调用 Stitch 写操作即可检索、模拟应用并审阅结果。

## 快速开始

输入：“把企业微信预约管理 Web 页导入 Stitch。只用演示素材，先返回本地结果与验证范围。”

输出：路由 /orders → 本地 .stitch/orders.html；DESIGN.md 来源 src/theme.css；远程状态未执行，等待已授权上传阶段。

验证：每条路由都有 HTML、来源和真实返回 ID；若示例无远程环境，明确远程状态未执行。

## 典型场景

输入：“将 Vue 门店排班页连同视觉规范迁移；范围限当前需求。”

输出：按顺序列出按 stitch-extract-static-html 生成每条路由的独立 HTML，先检查资产闭合与脱敏。 按 stitch-extract-design-md 从当前源码生成 .stitch/DESIGN.md，保留 YAML name/colors 和来源。 在已有上传授权范围内用 stitch-manage-design-system 建立项目系统，记录返回的 sourceScreen 与实例 id。 最后返回已处理对象与来源，未运行的项目单列。

验证：DESIGN.md 与 HTML 来自同次快照。

## 高级场景

输入：“按 /orders、/settings 两条路由生成可追踪导入清单；定制参数为路由列表、视口、主题和输出目录；例如只处理 /orders、1280×800、深色。”

输出：保留所选参数、路由到屏幕映射；HTML/设计系统同源检查；分阶段恢复清单，提供上传状态未确认时保留本地产物并停止后续写入的判据；假设不冒充实际配置。

## 异常处理

输入：“把企业微信预约管理 Web 页导入 Stitch，但暂时缺少源码目录和可运行 URL 或构建产物。”

输出：“先给本地假设草案。需要补充：源码目录和可运行 URL 或构建产物，用于确定真实来源；未执行依赖该来源的写操作。”不返回空答复，也不伪造成功。

## 避免误触发与验证

输入：“只保存本地 HTML，不扩大任务。”

输出：“使用stitch-extract-static-html；交接当前素材和请求，当前入口不执行额外动作。”

检查：以上五种请求分别检索快速、典型、高级、失败、边界路径；检查输出中的 ID、token、运行结论是否均有输入/回执依据。此人工应用检查不等价于独立模型触发率统计。
