# Stitch 数据看板实现：深度 FAQ

## Q1：遇到“把私密 RPC key 放 VITE_*”怎样处理？

客户端环境变量会打包公开，改服务端代理。处理后验证：筛选/分页改变 queryKey，未以 mock 冒充后台。

## Q2：遇到“表格全部写 div”怎样处理？

使用 table 或有完整语义的现有表格。处理后验证：语义表格与键盘焦点可用。

## Q3：遇到“接口失败填虚假业务数字”怎样处理？

保留错误态与重试。处理后验证：VITE_* 仅包含公开配置。

## Q4：遇到“假定 design.md linter 已存在”怎样处理？

用项目现有检查与本地语义核对。处理后验证：筛选/分页改变 queryKey，未以 mock 冒充后台。

## Q5：遇到“看板默认加入钱包”怎样处理？

仅在明确链上需求时增加只读适配。处理后验证：语义表格与键盘焦点可用。

## Q6：多人或多平台交接怎样保持一致？

共享接口适配器、queryKey、分页策略、断点、币种/单位；按角色分配素材、实现与验收。交接必须带筛选/分页改变 queryKey，未以 mock 冒充后台的证据，以及已完成/待确认状态。不同平台的输出路径与版本分别记录，不能把一个平台成功外推到其他平台。

## Q7：素材含真实客户信息，或者工具缺失怎么办？

先输出本地草案与缺失清单，不运行依赖项。客户字段替换成明确的“演示门店/演示订单”；删除会话、cookie、签名 URL，截图中的个人信息也要脱敏。只检查与任务有关的文件；安装工具前说明具体依赖、范围和影响，已有批准有效。
