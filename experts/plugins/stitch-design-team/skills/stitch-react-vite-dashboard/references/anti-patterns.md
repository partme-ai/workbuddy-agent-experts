# Stitch 数据看板实现：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 把私密 RPC key 放 VITE_* | 客户端环境变量会打包公开，改服务端代理。 |
| 表格全部写 div | 使用 table 或有完整语义的现有表格。 |
| 接口失败填虚假业务数字 | 保留错误态与重试。 |
| 假定 design.md linter 已存在 | 用项目现有检查与本地语义核对。 |
| 看板默认加入钱包 | 仅在明确链上需求时增加只读适配。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理将门店运营稿实现为预约量看板的本地方案；需要补充：目标 React/Vite 工程和锁定版本（确定来源）、Stitch HTML/截图及 DESIGN.md（决定映射）、接口契约、分页规则和演示数据（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
