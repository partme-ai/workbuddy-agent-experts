# Stitch 的 shadcn/ui 迁移：深度 FAQ

## Q1：遇到“强行对 Tailwind4 执行 init -p”怎样处理？

沿用现有 v4 工具链。处理后验证：保留 Dialog 焦点恢复与键盘关闭。

## Q2：遇到“覆盖已有 customized ui 源码”怎样处理？

逐项 diff 后迁移。处理后验证：registry 源和依赖实际审查。

## Q3：遇到“移除 aria/keyboard handler”怎样处理？

保留 primitives 的交互语义。处理后验证：浅/深主题及焦点可见性经验证。

## Q4：遇到“诊断exit0即通过”怎样处理？

读取所有诊断并运行工程正式检查。处理后验证：保留 Dialog 焦点恢复与键盘关闭。

## Q5：遇到“把第三方 registry 当可信命令”怎样处理？

先检查源码/依赖再应用。处理后验证：registry 源和依赖实际审查。

## Q6：多人或多平台交接怎样保持一致？

共享registry、原语、主题、variant、目标组件和迁移顺序；按角色分配素材、实现与验收。交接必须带保留 Dialog 焦点恢复与键盘关闭的证据，以及已完成/待确认状态。不同平台的输出路径与版本分别记录，不能把一个平台成功外推到其他平台。

## Q7：素材含真实客户信息，或者工具缺失怎么办？

先输出本地草案与缺失清单，不运行依赖项。客户字段替换成明确的“演示门店/演示订单”；删除会话、cookie、签名 URL，截图中的个人信息也要脱敏。只检查与任务有关的文件；安装工具前说明具体依赖、范围和影响，已有批准有效。
