# 上传本地资产到 Stitch：深度 FAQ

## Q1：把 key 放进命令参数，怎样检查与改正？

诊断：检查拟执行命令是否包含明文 key；任何密钥参数都会进入进程 argv。
处理：先运行本地设置器，由 `platform_secret_provider()` 从环境或受限用户配置读取；不要扫描其他客户端配置或把 key 粘贴到会话。
验证：CLI 不识别密钥参数；测试输出与错误流不含测试凭据；配置缺失时在发请求前退出。

## Q2：证书验证失败，可以关闭 TLS 校验吗？

诊断：先区分证书链缺失、主机名错误与错误的系统时间；不能从所有 TLS 错误推断为“没装 certifi”。
处理：使用已安装 certifi 或可信 CA 文件的 SSL_CERT_FILE 配置，核对官方 HTTPS 根地址。不得使用不验证证书的 SSL context。
验证：确认实际创建的 SSL context 保持证书和主机名验证；错误 CA/主机名仍拒绝连接。在合法环境修好 CA 后才进行已授权请求，不能用 MIME 映射测试代替 TLS 验证。

## Q3：响应字段可能携带私密内容，怎么保证摘要安全？

诊断：不仅检查键名，还检查当前顶层 `results`、每项 `screen` 及 `name` 的类型和格式。
处理：只接受目标项目下的屏幕资源路径。异常字段、重复标识或无结果使整次结果未知；额外业务字段丢弃。
验证：离线测试输入对象型 name、私密正文、错误项目和异常集合时应得到不含原值的 ValueError；CLI 非零退出，不打印私密内容，不重发。合法结果只保留已验证 ID。

## Q4：返回 302/307 时为何不继续跳转？

诊断：重定向可能把 X-Goog-Api-Key 或 POST 正文交给另一个主机，也可能重复创建屏幕。
处理：上传 opener 禁止自动重定向；核对服务端地址和代理配置，保持本次结果待确认。
验证：NoRedirect 不生成后续请求；离线检查或网络审计只能看到一次上传尝试，输出不含 Location 的私密内容。拒绝重定向不等于确认服务端没有创建结果。

## Q5：上传超时、空 JSON 或实例缺失，怎样恢复？

诊断：确认请求是否已发送。{}、[]、空 `results` 或缺失 `results[].screen` 都不足以证明成功，也不足以证明远程未写入。
处理：先 get_project、list_screens、get_screen 对账，检查目标项目、候选屏幕、时间及关联；没有候选时记录 get_screen 不能执行的原因。保留本地输入和未知状态。
验证：对账记录完整且没有自动第二次 POST；只有实际状态证明需要新写入时才提出新操作。文件 MIME 正确不能证明上传恢复成功。

## Q6：多人交接时必须交付什么？

诊断：仅有本地文件路径或 session 信息不足以让下一位维护者创建系统。
处理：记录目标 projectId、文件类型/大小、title、generated-by、上传是否已发送及已验证的 screen/instance 标识；不转交密钥和完整响应。
验证：接手者能用真实 sourceScreen 与实例 id 查询同一项目；若结果未知，交接的是待对账状态，而不是成功标记。不同项目的同名文件不能共用标识。

## Q7：素材含客户信息或本机缺少依赖怎么办？

诊断：检查 HTML 文本、图片和元数据是否包含姓名、电话、订单或会话；检查当前 Python 环境是否能导入脚本和使用有效 CA。
处理：先产出本地上传清单，改用演示内容并重新检查实际文件。缺依赖时说明准确工具与影响，沿用已有安装授权，没有授权则不安装也不上传。
验证：传输的正是审核过的文件版本；输出不含凭据/原文；未满足前提时请求次数为0。仅把文件名改为 demo 不算脱敏。

## Q8：技能许可证是否同时覆盖品牌素材？

诊断：区分本技能实现、第三方依赖和上传的字体/图片/客户截图。
处理：技能遵循仓库 Apache-2.0 与 NOTICE；素材分别记录来源、许可与使用范围，未确认的商用许可标为待核验。
验证：交付清单保留所需版权声明，每项素材的授权结论都有来源；不会把“代码开源”写成“所有图片可商用”。必要时交由有资质的审核者确认。
