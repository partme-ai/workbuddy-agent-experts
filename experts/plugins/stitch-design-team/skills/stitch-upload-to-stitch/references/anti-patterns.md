# 上传本地资产到 Stitch：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 把 key 放进命令参数 | 先用本地设置器保存，由 `platform_secret_provider()` 读取。 |
| 证书失败关闭验证 | 提供有效 CA 环境配置并保留 TLS 校验。 |
| 调用失败打印完整 HTTP body | 只报告状态和恢复建议。 |
| 把 302/307 当成功自动跳转 | 拒绝跳转，检查官方端点。 |
| 超时立即再发 batchCreate | 先读取三项状态，避免重复屏幕。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理上传脱敏的门店预约页 HTML 的本地方案；需要补充：真实 projectId、支持格式的已审核本地文件、已由设置器配置的凭据与上传授权。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
