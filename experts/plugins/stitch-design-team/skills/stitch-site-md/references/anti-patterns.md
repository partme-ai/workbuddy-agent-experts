# 编写 Stitch 站点蓝图：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 声称七节但只列六节 | 统一六节并列明创作边界。 |
| 页面文件存在就标完成 | 读取实际验证证据。 |
| 未知 projectId 留占位字符串 | 写未关联且禁止作为 MCP 参数。 |
| 默认目录覆盖既有结构 | 沿用实际站点根目录。 |
| 创作自由被当无上限任务 | 明确非目标、轮次和停止条件。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理为门店预约站建立页面蓝图的本地方案；需要补充：站点需求说明（确定来源）、实际文件树与已验证页面状态（决定映射）、品牌风格和可选真实 projectId（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
