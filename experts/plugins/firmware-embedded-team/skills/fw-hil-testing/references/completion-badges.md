# 完成徽章定义（completion-badges）

read-when：声明验证状态、评审他人的"已验证/可发货"说法、或决定能否进入发布门禁时。

## 1. 三级徽章

| 徽章 | 取得条件 | 允许声明（上限） | 禁止声明 | 证据要求 |
|---|---|---|---|---|
| `Build Verification Only`（B0） | 构建通过、镜像产出 | "编译产出镜像，未运行验证" | 任何"可启动/可用/稳定"表述 | 构建日志 + 产物 sha256 |
| `Boot Verified (QEMU)`（B1） | 无板环境可引导 + 冒烟通过（fw-emulation） | "QEMU 内可启动，X 功能冒烟通过" | 任何暗示真机通过的说法 | 模拟器启动日志 + 冒烟记录（标明 QEMU） |
| `HIL Verified`（B2） | 验收矩阵全行真机证据齐（fw-hil-testing） | "真机矩阵全行通过，证据可查" | 超出矩阵覆盖范围的推断（如"批量没问题"） | 证据包：每行截图/日志/测量值 + 设备标识 + 版本 + 日期 |

遗留标记 **`Pending HIL`**：其他技能（esp32-debug、esp32-ota、openwrt-serial-recovery 等）挂在**单行**上的"待真机验证"标记，继续有效；语义 = 该行尚未取得 B2 证据。徽章是**交付物级**状态，Pending HIL 是**行级**状态——B2 的前提是没有任何行仍挂 Pending HIL。

## 2. 越级禁令与常见越级话术

| 话术 | 为什么越级 | 合规说法 |
|---|---|---|
| "QEMU 都过了，直接发货" | B1 ≠ B2：QEMU 无真实电气、存储介质、断电、无线环境与长时老化 | "B1 已达成；真机矩阵未跑，暂不可发货" |
| "镜像编出来了，应该能用" | B0 无任何运行证据 | "Build Verification Only，未运行验证" |
| "板上跑过"（实际是旧版本/别的设备） | 证据的设备/版本对不上，按无效证据处理 | 补齐与目标版本、目标设备匹配的证据再评级 |
| "单台 HIL 全绿，批量没问题" | B2 只覆盖单台；批量是商业门禁 G2–G4 的事 | "单台 HIL Verified；批量按 G1→G4 逐级放行" |

## 3. 与其他技能的衔接

- **收敛**：各技能的 Pending HIL 行汇总到 `fw-hil-testing` 的验收矩阵销项；
- **升级**：B0 → B1 走 `fw-emulation`（无板引导冒烟）；B1 → B2 走 `fw-hil-testing`（真机矩阵）；
- **下游**：B2 + 证据包是 `fw-release-gate` 发布门禁的徽章前置；渠道版徽章 < B2 时只能进内部/测试渠道并显式标注；
- **背语落地**：fw-core 的"构建成功 ≠ 硬件可用"由 B0/B1/B2 落成可检查的状态机。
