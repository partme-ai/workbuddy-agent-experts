# 管理 Stitch 项目设计系统：本地应用验证

以下是完整的中文请求与预期响应契约，使用演示资料；不是远程执行记录。不调用 Stitch 写操作即可检索、模拟应用并审阅结果。

## 快速开始

输入：“把门店后台 DESIGN.md 建为项目系统。只用演示素材，先返回本地结果与验证范围。”

输出：离线输入实例 {id:'demo-i',sourceScreen:'projects/123/screens/a',x:9} → 请求实例只保留 id/sourceScreen；未调用 apply。

验证：selectedScreenInstances 不含 x/y/width/height；若示例无远程环境，明确远程状态未执行。

## 典型场景

输入：“给预约列表和详情两屏应用现有系统；范围限当前需求。”

输出：按顺序列出检查 DESIGN.md 的 name/colors、颜色角色、字体和圆角；没有原素材时只生成标为建议的本地草案。 已有授权覆盖上传时上传文档，记录返回的 sourceScreen 和 screenInstance.id；否则提交具体资产清单。 按当前 schema 调用 create_design_system_from_design_md，或用现有系统；不把本地文件存在视为远程已应用。 最后返回已处理对象与来源，未运行的项目单列。

验证：系统 assetId 来自 list_design_systems。

## 高级场景

输入：“只读核对项目当前设计系统与屏幕实例；定制参数为系统名称、主题、指定实例列表、仅查询/创建/应用模式。”

输出：保留所选参数、实例过滤；系统与屏幕分阶段状态；项目级 token 去重，提供上传、创建、应用分别有状态，失败不串行继续的判据；假设不冒充实际配置。

## 异常处理

输入：“把门店后台 DESIGN.md 建为项目系统，但暂时缺少真实 projectId 和可用 MCP schema。”

输出：“先给本地假设草案。需要补充：真实 projectId 和可用 MCP schema，用于确定真实来源；未执行依赖该来源的写操作。”不返回空答复，也不伪造成功。

## 避免误触发与验证

输入：“只写本地设计文档，不扩大任务。”

输出：“使用stitch-design-md；交接当前素材和请求，当前入口不执行额外动作。”

检查：以上五种请求分别检索快速、典型、高级、失败、边界路径；检查输出中的 ID、token、运行结论是否均有输入/回执依据。此人工应用检查不等价于独立模型触发率统计。
