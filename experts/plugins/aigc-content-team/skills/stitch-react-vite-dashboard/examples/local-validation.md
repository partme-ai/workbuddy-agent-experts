# Stitch 数据看板实现：本地应用验证

以下是完整的中文请求与预期响应契约，使用演示资料；不是远程执行记录。不调用 Stitch 写操作即可检索、模拟应用并审阅结果。

## 快速开始

输入：“将门店运营稿实现为预约量看板。只用演示素材，先返回本地结果与验证范围。”

输出：预约筛选=待确认，接口演示返回 [] → 表格标题与筛选保留，显示“暂无预约”，不展示编造统计。

验证：筛选/分页改变 queryKey，未以 mock 冒充后台；若示例无远程环境，明确远程状态未执行。

## 典型场景

输入：“为订单表格增加查询和空/错/加载状态；范围限当前需求。”

输出：按顺序列出把 DESIGN.md 颜色、字体、间距映射到项目 CSS 变量，记录来源。 拆分页面/展示组件/hooks，保留语义 table、label、焦点和路由。 按接口契约设置 queryKey、查询函数、分页和加载/空/错误/重试状态；无接口用明确标记的演示适配器。 最后返回已处理对象与来源，未运行的项目单列。

验证：语义表格与键盘焦点可用。

## 高级场景

输入：“明确需求下展示链上只读数据；定制参数为接口适配器、queryKey、分页策略、断点、币种/单位。”

输出：保留所选参数、异步状态矩阵；数据来源标注；公开配置边界，提供VITE_* 仅包含公开配置的判据；假设不冒充实际配置。

## 异常处理

输入：“将门店运营稿实现为预约量看板，但暂时缺少目标 React/Vite 工程和锁定版本。”

输出：“先给本地假设草案。需要补充：目标 React/Vite 工程和锁定版本，用于确定真实来源；未执行依赖该来源的写操作。”不返回空答复，也不伪造成功。

## 避免误触发与验证

输入：“普通单个卡片转换，不扩大任务。”

输出：“使用stitch-react-components；交接当前素材和请求，当前入口不执行额外动作。”

检查：以上五种请求分别检索快速、典型、高级、失败、边界路径；检查输出中的 ID、token、运行结论是否均有输入/回执依据。此人工应用检查不等价于独立模型触发率统计。
