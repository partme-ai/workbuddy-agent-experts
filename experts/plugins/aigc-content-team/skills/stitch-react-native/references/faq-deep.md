# Stitch 转 React Native：深度 FAQ

## Q1：从 HTML 复制了 div、span 或 onClick，怎样确认映射正确？

诊断：检查 JSX 标签和事件名；RN 不是浏览器 DOM，直接文本也不能任意放在 View 下。
处理：容器改 View，文本改 Text，按钮改 Pressable 和 onPress，输入使用 TextInput 的对应事件。
验证：AST 不含受检 DOM 标签；人工检查所有文本节点位于 Text，事件参数与当前 RN 类型契约匹配。AST 不检查所有事件和运行时文本错误，仍需项目类型检查和实际页面验证。

## Q2：横排元素变成竖排，该怎样定位？

诊断：查看容器是否依赖 Web 的 flex 行方向假设，以及是否存在覆盖样式。
处理：按设计在目标容器明确设置 flexDirection: 'row'；竖向表单继续使用 column，不对所有 View 全局替换。
验证：在目标尺寸下检查子项的实际横纵顺序、换行与溢出；旋转设备后布局仍符合设计。主题颜色或 Image 尺寸不能验证排列方向。

## Q3：长列表放在 ScrollView 里产生嵌套滚动警告怎么办？

诊断：检查同方向 ScrollView 内是否嵌套 FlatList/SectionList，以及列表是否失去虚拟化。
处理：将页面头尾放入 ListHeaderComponent/ListFooterComponent，或用 View 包裹列表；保留稳定 keyExtractor 和分页状态。
验证：用长列表在目标平台检查该嵌套警告消失、滚动和分页可用，离屏条目按列表机制处理。safe-area 或导航通过不代表列表虚拟化已正确。

## Q4：AST 已通过，能否宣布真机交付完成？

诊断：本脚本只检查 exported Props、字面颜色与 DOM 标签；它不解析完整依赖，也不执行原生布局、导航或键盘。
处理：分别运行目标工程 typecheck/build，再在已有授权的模拟器或真机验证导航、safe-area、键盘与组件状态；缺工具明确标记未执行。
验证：报告分别列 AST、类型/构建、平台、设备与检查结果；只有实际平台操作的记录才支持该平台通过。不能把“无DOM标签”重复写成真机证据。

## Q5：已有缓存是否应全部刷新？

诊断：比较用户选定屏幕与 .stitch 元数据中的 projectId、screenId、来源时间和刷新意图。
处理：只刷新获准的屏幕，先下载到暂存文件，失败保留旧文件；复用缓存时标明所复用的来源和时间，不更新为虚假的当前同步时间。
验证：未选中资产的摘要/内容不变；被选中资产与新的回执和时间对应；失败路径测试证明旧文件保留。图片有尺寸并不能证明缓存来源正确。

## Q6：iOS 与 Android 团队怎样交接差异？

诊断：比较两端目标版本、导航方式、阴影/safe-area/键盘行为，不能把一个平台截图当另一平台证据。
处理：共享主题来源、Props、页面范围和平台分支；为每端记录构建命令、设备条件与未解决项。
验证：两端各有自己的类型/构建和平台验证状态；没有运行的一端标“未执行”。交接者能定位对应代码与资产版本。

## Q7：素材含真实客户内容或缺少 RN 依赖怎么办？

诊断：检查演示数据、avatar URL 和截图是否包含私人身份；区分缺 @swc/core 的 AST 环境与缺 RN/导航/安全区依赖的目标工程。
处理：使用明确演示数据；先完成有依据的映射说明，精确列出缺少的包/工程配置。安装按已有授权执行，不默认为每次转换全局安装工具。
验证：示例不携带个人信息或私密URL；各检查使用的实际依赖路径和版本可追踪。复用已有SWC只证明AST检查可运行，不能证明RN工程可编译。

## Q8：商用时要保留哪些声明？

诊断：分别核对技能源码、复制的组件、图像、字体和第三方原生依赖。
处理：保留上游要求的版权和 NOTICE；生成的新业务代码不附加无关版权头，但复制上游实现不能删除必要声明。
验证：产物来源清单与相应许可一致，无法核验的素材单列待处理；不能从本技能的 Apache-2.0 推断所有设计素材和依赖具有同一许可。
