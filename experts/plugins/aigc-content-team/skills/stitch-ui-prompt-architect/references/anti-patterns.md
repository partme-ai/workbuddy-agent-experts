# Stitch 提示词设计：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 把模糊需求直接转发 | 补编号布局与具体控件文案。 |
| 一个本地 DESIGN.md 就当远程已应用 | 要求明确系统状态，否则内联fallback。 |
| targeted edit 重述整页并扩大改动 | 只给区域和变化。 |
| Path B 漏掉 Components | 两条路径都输出三段。 |
| 加虚假用户数提升可信度 | 仅使用用户提供的事实。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理润色门店预约页的模糊 Stitch 提示的本地方案；需要补充：页面目的、内容与目标设备（确定来源）、可选 Design Spec、DESIGN.md 或框架名（决定映射）、项目系统是否已应用及执行模式（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
