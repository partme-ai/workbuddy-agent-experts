# Stitch 提示词设计：本地应用验证

四个代码块都是可直接交接的完整提示词。示例只输出文本，不调用 Stitch 写操作；演示品牌与建议值不是已观察的生产配置。

## 快速开始：模糊需求走 Path A

输入：“帮我把‘门店预约页面’写成 Stitch 提示词。先按手机页面给草案，主题由你提出，不执行生成。”

预期提示词（prompt-only 内联 token 模式）：

```text
[Context]
为门店顾客提供手机端预约列表，核心操作是查看预约并发起新预约。
本地建议主题：浅色；画布白 (#ffffff) 为背景，行动蓝 (#2563eb) 用于“新建预约”，正文深灰 (#111827) 用于内容。
字体采用系统无衬线并包含中文回退；以上为提案，不代表远程项目已应用设计系统。
[Layout]
1. 顶部：标题“我的预约”，右侧“新建预约”操作。
2. 主区：按预约时间排列列表，单项含门店名、日期和状态。
3. 空态：显示“暂无预约”，提供“新建预约”入口。
[Components]
预约列表项以可点击区域展示详情；主按钮标签“新建预约”；
加载时保留列表骨架，读取失败显示“预约加载失败”和“重试”；
操作有可见焦点，状态文字不只依靠颜色区分。
```

验证：明确手机平台、目的、建议主题和实际中文文案；没有把新建页面误写成顶栏局部编辑。

## 典型场景：Spec 走 Path B，系统已应用

输入：“TABLET 预约列表；uView Pro 结构契约；编排器已确认远程系统 demo-system 已应用。只组装提示，不重复主题 token。”

系统标识 demo-system 由编排器在工具参数中单独传递，不声称这个演示 ID 已真实存在。

```text
[Context]
平板端门店预约管理页，供店员查询和确认预约。采用提供的 uView Pro 组件结构约束。
项目设计系统由编排器单独传递；本提示只指定内容、布局与交互。
[Layout]
1. 顶栏：标题“预约管理”，右侧用户菜单。
2. 筛选区：日期范围、“全部/待确认/已确认”状态选择，以及“查询”操作。
3. 主区：预约列表，展示门店、到店时间、演示客户标识、状态与“查看详情”。
4. 底部：分页控制，保留当前筛选条件。
[Components]
日期选择、状态选择、查询按钮、预约列表项和分页控件沿用所给结构契约；
查询加载时禁用重复提交并显示加载状态；
无结果显示“未找到预约”，失败显示“加载失败，请重试”；
确认动作显示结果反馈，实际接口由后续实现阶段对接。
```

验证：三段顺序固定；无 hex、字体、颜色角色、主题和圆角 token；提供的框架契约只用于结构，未自动增加后端接口。

## 高级场景：targeted edit

输入：“现有平板 Stitch 订单页，只在头像前增加搜索订单输入，其余保持不变。”

```text
[Context]
仅编辑现有平板订单页顶栏，保留其余页面结构、内容和设计系统。
[Layout]
1. 在当前用户头像之前插入搜索输入，保留头像与现有操作顺序。
[Components]
搜索输入的标签为“搜索订单”，占位为“输入订单号”；
提供清除动作、可见焦点和键盘提交；
输入为空时保留现有列表，不新增统计、侧栏或其他模块。
```

验证：只出现要求的区域与变化；没有重述或重建全页，没有隐式写调用。

## 异常处理：实际交付假设草案

输入：“润色‘预约页’这句话，但我暂时没有设备和具体流程。”

```text
[Context]
本地假设草案：暂按手机端顾客查看预约的页面设计，具体品牌和视觉系统待确认。
需要补充：目标设备（决定布局宽度）、主要用户与操作（决定顾客列表还是店员管理页）。
这些缺项不影响先审阅本提示，但不能视为已批准的实现需求。
[Layout]
1. 顶部显示“我的预约”标题。
2. 主区先呈现预约列表，单项展示门店、预约时间和状态。
3. 没有数据时展示“暂无预约”，不假定存在支付或取消功能。
[Components]
列表项提供“查看详情”；加载中显示骨架，读取失败提供“重试”；
暂不添加未明确授权的业务动作；视觉 token 待收到品牌资料或确认提案后补齐。
```

验证：确实有可用的三段草案和明确假设，同时列出缺项及影响；没有仅承诺“先给草案”却不提供产物。

## 避免误触发

输入：“直接用 Stitch 生成上面的页面。”

输出：“交给 stitch-ui-designer 执行，并传递已确认提示与项目系统状态；本入口的交付是提示文本，尚未生成屏幕。”

这些结构/应用断言不等价于独立模型触发率或真实生成效果测量。
