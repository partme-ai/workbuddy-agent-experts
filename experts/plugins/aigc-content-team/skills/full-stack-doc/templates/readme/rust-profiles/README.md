# Rust README 领域剖面选择器

> 本目录不是六套项目专属 README，而是与 `../README-Rust项目模板.md` 组合使用的可选章节库。

## 使用方法

1. 先从 `../README-Rust项目模板.md` 复制 Rust 工程共有部分。
2. 从 Cargo manifests、源码、CI、测试、规范和发布元数据确认项目事实。
3. 按下表选择零个、一个或多个领域剖面。
4. 把剖面章节放入母模板建议的位置，并统一最终章节编号。
5. 删除未实现、无证据或不适用的示例，不能用“暂无”保留空壳。
6. 运行模板校验，并在目标仓库验证命令、链接和示例。

## 选择矩阵

| 项目特征 | 必选剖面 | 可组合剖面 |
|---|---|---|
| 处理 XLSX、DOCX、PDF、OFD、图片、压缩包或其他结构化文件 | [文档与文件格式处理](文档与文件格式处理剖面.md) | 上游兼容、工具箱 |
| 从另一语言、标准实现或上游库迁移功能 | [上游兼容与移植](上游兼容与移植剖面.md) | 文档格式、工具箱、安全框架 |
| 包含大量独立 crate、Facade 和 features | [大型工具箱 Workspace](大型工具箱Workspace剖面.md) | 上游兼容 |
| 提供登录、鉴权、Token、会话、权限或安全中间件 | [认证与安全框架](认证与安全框架剖面.md) | 上游兼容、设计阶段 |
| 尚无可构建 Cargo workspace 或尚未形成可调用实现 | [纯设计阶段](纯设计阶段剖面.md) | 上游兼容、安全框架 |
| 维护中英双语 README | [多语言 README 布局](多语言README布局剖面.md) | 任意剖面 |

## 组合示例

```text
电子表格兼容库
  = Rust 母模板
  + 文档与文件格式处理
  + 上游兼容与移植
  + 多语言布局

大型通用工具箱
  = Rust 母模板
  + 大型工具箱 Workspace
  + 上游兼容与移植（存在上游行为权威时）

尚未实现的认证框架设计
  = 纯设计阶段
  + 认证与安全框架中的“设计状态”章节
  + 上游兼容与移植中的目标矩阵
```

## 章节插入建议

| 剖面 | 建议插入母模板位置 |
|---|---|
| 文档与文件格式处理 | “核心 API”之后、“后端、格式与可选引擎”之前或替换该节 |
| 上游兼容与移植 | 扩展“兼容、迁移与来源” |
| 大型工具箱 Workspace | 扩展“Workspace 与 crate 架构”和“Cargo Features” |
| 认证与安全框架 | “核心 API”之后、“安全”之前 |
| 纯设计阶段 | 替换安装、运行、测试和发布章节，不与其并存 |
| 多语言 README 布局 | 生成 README 前执行，不进入最终正文或仅保留语言导航 |

## 组合约束

- “纯设计阶段”与 crates.io 安装、运行成功、测试通过、覆盖率和发布章节互斥。
- “上游兼容”必须给出权威版本、统计分母和验证方法；只有名称相似不构成兼容。
- “文档格式处理”中的支持矩阵按实际读、写、编辑、保真和测试分别声明。
- “大型工具箱”不得用一个总徽章暗示每个 crate、feature 和目标平台都已验证。
- “认证与安全框架”不得把示例默认值包装成生产安全建议。
- 多语言版本的命令、坐标、crate、features、版本和状态必须完全一致。

## 交付检查

- [ ] 母模板中的项目状态、MSRV、Edition、Resolver 和 crate 信息来自当前 manifest
- [ ] 所选剖面与项目真实职责相符
- [ ] 剖面内的能力状态与源码和测试一致
- [ ] 未选择剖面的领域内容没有误入最终 README
- [ ] 计划、实验、部分支持和稳定能力有明确区别
- [ ] 语言布局与仓库现有链接和文件名一致
- [ ] 最终 README 仍只有一个 H1，章节顺序连续
