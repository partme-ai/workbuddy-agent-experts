# Stitch 设计执行编排：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 无工具也称生成成功 | 只输出提示文本与未执行状态。 |
| 每次 edit 新建项目 | 复用既有项目及屏幕。 |
| 已应用系统重复内联主题 | 分离系统ID与内容布局提示。 |
| 中断立即重发生成 | 先完整三探针对账。 |
| 把清理等同删除许可 | 删除前取得明确确认。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理用 Stitch 生成门店预约平板页的本地方案；需要补充：目标项目及新建/编辑/变体意图（确定来源）、界面需求、设备和已有设计系统（决定映射）、可用工具 schema、目标屏幕及写入范围（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
