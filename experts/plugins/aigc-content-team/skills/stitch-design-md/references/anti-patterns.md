# Stitch 语义设计系统文档：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| rounded-xl 原样当设计语言 | 写可理解的形状描述并记录来源。 |
| 只写蓝色 | 列确切值和功能角色。 |
| 把建议断点当原设计 | 标明建议与观察区别。 |
| 引用不存在的官方 lint 脚本 | 执行本地语义规则，说明来源。 |
| 缺资产覆盖已有 DESIGN.md | 保留旧版并写部分草案。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理从门店预约页面提炼颜色角色的本地方案；需要补充：实际 HTML/截图或 Stitch 标识（确定来源）、主题与代表性页面范围（决定映射）、观察来源和希望输出的文件路径（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
