# 从源码提取设计系统：本地应用验证

以下是完整的中文请求与预期响应契约，使用演示资料；不是远程执行记录。不调用 Stitch 写操作即可检索、模拟应用并审阅结果。

## 快速开始

输入：“从企业微信预约 Web 页的 CSS 提取主色与间距。只用演示素材，先返回本地结果与验证范围。”

输出：name: 门店预约；colors.primary: '#2563eb'（演示输入）；Source: src/theme.css 的 --brand-primary；氛围为源码推断，尚未渲染。

验证：颜色值可回溯到源码且近似色未被静默合并；若示例无远程环境，明确远程状态未执行。

## 典型场景

输入：“构建失败时读取 Angular 模板和主题；范围限当前需求。”

输出：按顺序列出按框架读取现有 references 中的提取指南；先主题后组件，记录具体文件与选择器。 提取颜色角色、字体、间距、圆角、组件状态和响应式条件，区分事实和建议。 写 .stitch/DESIGN.md：YAML name/colors 加六节语义文档；未知 Project ID 省略，使用 Source。 最后返回已处理对象与来源，未运行的项目单列。

验证：name/colors YAML 可解析。

## 高级场景

输入：“比较门店后台深浅主题差异并记录来源；定制参数为主题模式、组件范围、语言和路径；例如只提取深色按钮/表单。”

输出：保留所选参数、token 溯源表；近似色差异清单；框架按需路由，提供断点和交互状态区分已观察与建议的判据；假设不冒充实际配置。

## 异常处理

输入：“从企业微信预约 Web 页的 CSS 提取主色与间距，但暂时缺少前端源码根目录。”

输出：“先给本地假设草案。需要补充：前端源码根目录，用于确定真实来源；未执行依赖该来源的写操作。”不返回空答复，也不伪造成功。

## 避免误触发与验证

输入：“只看截图提炼语义，不扩大任务。”

输出：“使用stitch-design-md；交接当前素材和请求，当前入口不执行额外动作。”

检查：以上五种请求分别检索快速、典型、高级、失败、边界路径；检查输出中的 ID、token、运行结论是否均有输入/回执依据。此人工应用检查不等价于独立模型触发率统计。
