# Stitch 有限页面构建循环：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| backlog 空就发明下一页 | 明确完成并停止。 |
| page: ../../secret | 拒绝路径，仅接受安全 slug。 |
| 本地 DESIGN.md 就当远程系统已应用 | 查系统状态再决定提示 token。 |
| 失败即重新生成 | 三项只读对账且记录 get_screen 无候选原因。 |
| 移动文件后旧版丢失 | 先暂存核对再整合，保留可恢复版本。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理接力完成门店预约站当前订单页的本地方案；需要补充：SITE.md、DESIGN.md 与当前 next-prompt.md（确定来源）、项目元数据、既有页面及授权轮次（决定映射）、可用 Stitch 工具和目标输出根目录（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
