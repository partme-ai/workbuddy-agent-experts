# 安全删除 Stitch 项目

## 快速开始

- “删除 Stitch 项目 123，先给我看准确目标。”
- “清理刚才创建的临时 Stitch 项目，但调用删除前让我确认。”
- “核对项目 `projects/123` 是否已经删除，不要重复删除。”

适用于设计师、开发者和验收人员清理自己有权管理的单个 Stitch 项目。团队交接必须保留项目来源和批准状态。

## 能力边界说明

### ✅ 擅长处理

- 预览单个项目的标题、纯 ID 和完整资源名。
- 经明确批准后调用一次 `delete_project`。
- 用 `list_projects` 做删除后的只读对账。

### ⚠️ 需要素材

- 来自当前工具结果的真实项目 ID 或 `projects/{project}`。
- 删除前可读取的目标项目元数据。
- 对展示出的准确目标作出的明确批准。

### ❌ 不适用场景及交接

- 批量清空账号项目 → 拒绝批量执行，改为逐项目审核。
- 用户只想归档本地 Harness 产物 → `stitch-delivery-harness`。
- 用户只想删除本地文件 → 使用目标工作区的文件管理流程。

## 安全工作流

1. 用 `get_project` 读取 `name: projects/{project}`，确认项目存在和标题；不得从模糊名称猜 ID。
2. 展示删除前预览：标题、纯项目 ID、准确完整目标 `projects/{project}`，说明远程删除不可撤销。
3. 等待用户针对该准确目标的明确批准。既往创建授权、一般“继续”或其他项目的批准均不适用。
4. 获得用户对准确目标的明确批准后，再取得宿主对这一次工具调用的运行时批准；Skill frontmatter 不预授权删除。随后仅调用一次 `delete_project`，参数为 `{"name":"projects/{project}"}`；超时、连接中断或未知响应时不得重发。
5. 只用 `list_projects` 对账：目标不再出现才记录为已删除；仍存在则记录未删除；无法确认则记录未知结果并停止。

## 安全与结果验证

不输出凭据、会话 cookie、签名 URL 或私有页面内容。仅操作用户明确指定且当前账号可见的项目。工具回执与对账是两份证据；没有只读对账时不得宣称删除完成。

## FAQ

**Q1：为什么批准前还要读取项目？** 防止过期或抄错 ID，并让用户看到准确目标。

**Q2：用户刚创建项目是否等于允许删除？** 不等于；删除需要单独、明确批准。

**Q3：删除调用超时怎么办？** 不重发，立即走 `list_projects` 只读对账。

**Q4：可以一次删除多个项目吗？** 不可以；本技能一次只处理一个准确目标。

**Q5：怎样算完成？** 删除调用之后，`list_projects` 已确认该项目不再存在。

**Q6：项目仍存在怎么办？** 报告未删除并停止；下一次调用需要新的明确批准。
