# 示例与 FAQ

## 示例

1. 采访短视频：三段横版采访 → 拉片 → 60 秒 9:16 粗剪 → 字幕 → 终版。
2. 成语故事：六张已批准插画 → 推拉平移 → 旁白与 SRT → 16:9 成片。
3. 电商产品：产品视频与授权音乐 → 节奏剪辑 → 1:1 和 9:16 两个计划。
4. Blender 交接：消费带哈希动画 MP4，不启动或控制 Blender。
5. 单镜头修改：删除 C03、延长 C04 → revision 2 → 仅重做受影响分段。
6. 中断恢复：检查 ledger → 复核回执 → 仅继续 Pending。

## 常见陷阱

- 把同步审阅视频当客户终版：它只用于内部核对镜号和镜头信息。
- 用旧批准运行新计划：任何 hash 或 round 变化都要重新批准。
- 把 URL 填入素材路径：先在授权流程中落成本地文件并登记哈希。
- 把 `SKIPPED` 写成 `PASS`：缺工具或证据必须保持真实状态。
- 直接传 FFmpeg 滤镜：改用计划中的封闭转场、运动、字幕和音轨字段。
- 无音轨原片直接跑 video-sync：先通过 Factory 规范化或提供有效音轨。

## FAQ

1. **能文生视频吗？** 0.1.0 不能；它能把本地素材自动编排成视频。
2. **为什么两次批准？** 粗剪和终版的成本、内容和输出规格不同。
3. **Chrome 缺失怎么办？** 仍可粗剪/终版，只跳过同步面板审阅。
4. **能继续失败任务吗？** Pending 可恢复，Failed 修复后必须新 round。
5. **字幕为什么不是烧录？** 当前 MP4 默认内嵌字幕轨，避免依赖 libass；发布平台可按需转码。
6. **能用外部音乐吗？** 只有在用户拥有许可并登记来源时可以。
7. **如何做横竖双版？** 创建两个输出规格和两份批准，复用未变化内容寻址分段。
8. **模型说通过就算通过吗？** 不算；确定性硬门和人工驳回优先。
