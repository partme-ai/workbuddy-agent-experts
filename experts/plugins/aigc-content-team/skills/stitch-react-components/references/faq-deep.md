# Stitch 转 React 组件：深度 FAQ

## Q1：遇到“用示例 style-guide 当项目主题”怎样处理？

从当前 HTML 提取到项目本地。处理后验证：AST 仅证明解析、Props 和字面 className hex 检查。

## Q2：遇到“AST 通过就称导航正常”怎样处理？

实际验证 Link 目标与桌面首页入口。处理后验证：所有主题角色来源于当前设计。

## Q3：遇到“把动态 className 当脚本已覆盖”怎样处理？

人工审查或项目样式检查补足。处理后验证：首页链接和各路由都有可验证目标。

## Q4：遇到“为每次同步覆盖旧资产”怎样处理？

按范围刷新并保留 provenance。处理后验证：AST 仅证明解析、Props 和字面 className hex 检查。

## Q5：遇到“把 screenId 转数字”怎样处理？

原样保留字符串。处理后验证：所有主题角色来源于当前设计。

## Q6：多人或多平台交接怎样保持一致？

共享页面范围、目标目录、路由器、主题模式、刷新策略；按角色分配素材、实现与验收。交接必须带AST 仅证明解析、Props 和字面 className hex 检查的证据，以及已完成/待确认状态。不同平台的输出路径与版本分别记录，不能把一个平台成功外推到其他平台。

## Q7：素材含真实客户信息，或者工具缺失怎么办？

先输出本地草案与缺失清单，不运行依赖项。客户字段替换成明确的“演示门店/演示订单”；删除会话、cookie、签名 URL，截图中的个人信息也要脱敏。只检查与任务有关的文件；安装工具前说明具体依赖、范围和影响，已有批准有效。
