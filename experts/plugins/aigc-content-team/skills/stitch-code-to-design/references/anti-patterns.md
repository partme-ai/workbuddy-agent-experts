# 前端源码导入 Stitch：反模式与 Gotchas

这些检查处理实际流程偏差；触发后按下列原因和修正采取行动。

| 错误做法 | 后果与正确处理 |
| --- | --- |
| 只上传 HTML | 同时提取 DESIGN.md，避免页面与项目系统脱节。 |
| 把 /orders 命名为 Page1 | 保留路由标题，方便后续定位。 |
| 源码提取后自动上传未授权页面 | 只处理当前清单内的资产。 |
| 超时后立即再次上传 | 先 get_project、list_screens、get_screen 对账。 |
| 网页截图含客户电话 | 换成演示数据并检查 HTML 文本和图片后再上传。 |

## 失败输出契约

先交付本地可完成部分，再指出具体缺项。例如：“已整理把企业微信预约管理 Web 页导入 Stitch的本地方案；需要补充：源码目录和可运行 URL 或构建产物（确定来源）、实际 projectId 与目标路由列表（决定映射）、上传范围和可共享的脱敏页面状态（确定可执行边界）。”

远程写入超时不等于失败：停止依赖该回执的操作，读取 get_project、list_screens、get_screen；没有候选则记录 get_screen 未执行及原因。不得重发同一未知结果的写请求。删除项目前需要明确确认；其他步骤沿用已有授权。

## 禁忌

- 不把上游快照的可选依赖当本机已安装的工具。
- 不把生成文件存在当作渲染、交互或远程验收证据。
- 不将示例标识/演示文案当成真实客户资产。
