# 前端源码导入 Stitch：深度 FAQ

## Q1：遇到“只上传 HTML”怎样处理？

同时提取 DESIGN.md，避免页面与项目系统脱节。处理后验证：每条路由都有 HTML、来源和真实返回 ID。

## Q2：遇到“把 /orders 命名为 Page1”怎样处理？

保留路由标题，方便后续定位。处理后验证：DESIGN.md 与 HTML 来自同次快照。

## Q3：遇到“源码提取后自动上传未授权页面”怎样处理？

只处理当前清单内的资产。处理后验证：上传状态未确认时保留本地产物并停止后续写入。

## Q4：遇到“超时后立即再次上传”怎样处理？

先 get_project、list_screens、get_screen 对账。处理后验证：每条路由都有 HTML、来源和真实返回 ID。

## Q5：遇到“网页截图含客户电话”怎样处理？

换成演示数据并检查 HTML 文本和图片后再上传。处理后验证：DESIGN.md 与 HTML 来自同次快照。

## Q6：多人或多平台交接怎样保持一致？

共享路由列表、视口、主题和输出目录；例如只处理 /orders、1280×800、深色；按角色分配素材、实现与验收。交接必须带每条路由都有 HTML、来源和真实返回 ID的证据，以及已完成/待确认状态。不同平台的输出路径与版本分别记录，不能把一个平台成功外推到其他平台。

## Q7：素材含真实客户信息，或者工具缺失怎么办？

先输出本地草案与缺失清单，不运行依赖项。客户字段替换成明确的“演示门店/演示订单”；删除会话、cookie、签名 URL，截图中的个人信息也要脱敏。只检查与任务有关的文件；安装工具前说明具体依赖、范围和影响，已有批准有效。

## Q8：商用和品牌素材怎样处理？

本技能代码/文档遵循仓库 Apache-2.0 及 NOTICE；复制上游实现时保留所需版权声明。品牌字体、图像、截图内容及第三方依赖各自授权，不能由技能许可证推断其可商用；交付时列素材来源和未核验许可。此流程不会替用户作出法律授权结论。
